## Gotchas
- Devnet demos share the investor/issuer wallets: never run `make demo`, `make demo-plan15` or `make demo-trade` at the same time — `demo-full` checks each holder's cash delta and a concurrent subscribe/trade breaks it (2026-10-09).
- A Series with `open_action = None` keeps a stale 32-byte tail (Borsh shifts the fields, the max-size account keeps the old bytes); on hooked series the tail is non-zero — decoders must ignore it, never require zero padding (2026-10-09, task 91519).
- Public devnet RPC (`api.devnet.solana.com`) allows ~10 `getTransaction` per 10 s per IP (`x-ratelimit-method-limit: 10`), JSON-RPC batches included; the proof page paces itself to ~1/s after the first 429 (a series with 30 transactions takes ~35 s; a keyed `NEXT_PUBLIC_RPC_URL` takes ~2 s) (2026-10-09, task 1536).
- Next 15 `pageExtensions` with ONE entry reaches the app loader as a bare string and loses its dot (`Can't resolve private-next-app-dir/page`): the proof export uses `["proof.tsx", "proof.ts"]` (2026-10-09, task 1536).
- `sas-lib` 1.0.10 declares `@solana/kit ^5` but its instructions/PDAs work with kit 8 (cast the instruction to kit 8 `Instruction`). SAS accounts are pinocchio (1-byte discriminator, no Anchor header): Attestation = disc 2 · nonce · credential · schema · u32 len + data · signer · expiry i64 · token_account; expiry is NOT enforced by SAS on read.
- Anchor 1.2 `anchor deploy` uploads the IDL itself over the `--provider.cluster` RPC and aborts on failure; `ops/deploy.sh` passes `--no-idl` and uploads with retries over `RPC_URL` afterwards.
- Kit's preflight failure keeps program logs in `error.context.logs` (not `cause.logs`); `clients/ts/src/lib/tx.ts` extracts the Anchor error name from there so the API/console can show it.
- Devnet RPC reads (Helius, `confirmed`) can lag a confirmed transaction by ~20 s; UI refreshes must poll until the state moves, not for a fixed few seconds.
- Go is 1.26, not 1.25: `modernc.org/sqlite` (and x/sys, libc) require go ≥ 1.26, so go.mod says 1.26.0. Local/CI builds hid this by auto-downloading the toolchain; Docker (`GOTOOLCHAIN=local`) does not. CI reads the version from go.mod.
- Portal wallet signing: wallets sign via `signTransaction` on a web3.js `VersionedTransaction` (Kit wire bytes → deserialize → sign → Kit `getTransactionDecoder`); `signMessage` over transaction bytes is refused. Create ONE Kit signer per wallet and pass it to fee payer and instructions — Kit throws on two distinct signers with the same address.
- **IDL publish (Program Metadata Program) needs a non-public RPC**: with the 20-instruction IDL, `anchor idl upgrade` fails on api.devnet.solana.com with an opaque "transaction plan failed"; through Helius (`--provider.cluster "$RPC_URL"`) it succeeds. `ops/deploy.sh` uses `$RPC_URL` for the IDL steps only (`anchor deploy` prints the cluster URL, which would leak the API key into logs). Upgrades auto-extend program data (≈3.7 SOL rent for 527 KB + a temporary buffer) — top up the registrar from funder1 first.
- **Anchor 1.2 `Context<'info, T>` has one lifetime** (0.3x had four). Handlers that read `remaining_accounts` as `AccountInfo<'info>` use `Context<'info, X<'info>>`. `CpiContext::new(program_id: Pubkey, accounts)` takes the program id, not an AccountInfo.
- **Devnet SOL reserve**: `~/.config/qupon/funder1.json` (≈22 SOL) and `funder2.json` hold the human's devnet test SOL (Phantom path m/44'/501'/0'/0'); top up roles with `solana transfer --from ~/.config/qupon/funder1.json <pubkey> <sol> --allow-unfunded-recipient -u devnet` instead of rate-limited airdrops. Never commit these files.
- **LiteSVM ≥ 0.17 for SBPFv3**: Agave 4.3 platform-tools emit SBPFv3; LiteSVM 0.10 (Anchor 1.2 template default) fails `add_program` with `InvalidAccountData`. LiteSVM 0.17 needs host rustc ≥ 1.97.1 → `rust-toolchain.toml` pins 1.97.1, but workspace `rust-version` stays 1.89 (it also binds the SBF build, whose platform-tools rustc is 1.95).
- **Program id** `QPN1zdVm6PgMdJo4YxemtDxxbUczqaAk9sDsJQsJ2qd`; deploy keypair at `~/.config/qupon/program-keypair.json` (never in git); `make program-keypair` copies it into `target/deploy/` of each worktree. Avm's `anchor` lives in `~/.cargo/bin` — a Homebrew/npm `anchor` wrapper earlier on PATH is wrong (Makefile prepends `~/.cargo/bin`).
- **Toolchain pins via mise** (macOS dev box): `mise.toml` pins node 22 / go 1.26 / pnpm 9; Makefile, `ops/lib.sh`, `ops/doctor.sh` put `~/.local/share/mise/shims` first on PATH. `ops/wallets.sh` needs bash ≥ 4 (`brew install bash`).
- **Pausable blocks mint, burn and transfer.** Order for redemption: pay → `complete_action` (resume) → `retire_batch` (burn) → `close_series`.
- **Permanent delegate burn**: use `burn_checked` with the series PDA as delegate signer; works on thawed accounts only.
- **DefaultAccountState=Frozen**: ATAs are created frozen; `register_investor` thaws with the series PDA (freeze authority). Suspended investors are frozen again.
- **Token-2022 account size varies** (TLV extensions): never filter `getProgramAccounts` by `dataSize`; filter `memcmp{offset:0, bytes:<mint>}` and `memcmp{offset:32, bytes:<owner>}`.
- **Anchor 1.x transfer-hook `#[interface]` was removed** — we do not use transfer hooks at all.
- **`@coral-xyz/anchor` → `@anchor-lang/core`** (TS); we don't need it because Codama generates a Kit client.
- **Devnet public RPC**: 100 req/10 s/IP — use Helius for the Go service and tests on devnet; LiteSVM for unit tests.
- **Phantom dropped Blinks** — no Actions/Blinks.
- **Alpenglow**: `confirmed` ≈ `finalized` on devnet; nothing to change in code, but don't rely on `processed`.
- **SBPFv3**: address 0 reads succeed silently; stricter stack frames — avoid huge stack arrays in instruction handlers; box large accounts.
- **Clock in tests**: LiteSVM `svm.warp_to_slot()` and set the `Clock` sysvar to control `unix_timestamp`.
- **LiteSVM is not a cluster for limits**: it does not enforce the 1232-byte transaction size (a 10-triple `pay_batch` runs in tests but needs a lookup table on-chain), and its SPL Token program is the bundled p-token build, not a devnet dump (`tests/cu_benchmarks.rs`).
- **Z.ai plan**: GLM-5.3 consumes 3× quota at peak (Mon–Fri 11:00–15:00 Astana); Flash 0.4×; schedule heavy GLM runs off-peak.
- **Claude Code `-p` runs do not auto-wait on usage limits** — the orchestrator sleeps and retries.
- solana-go v2 puts the full request URL (query included) into its RPC errors — a keyed endpoint (`?api-key=`) leaks into logs and 502 bodies. Build clients with `chain.NewRPC` (keyless URL, key added on the wire); the executor also redacts `api-key=` from CLI output.
- Tailwind v4 only generates classes it finds verbatim in source: never build `md:table-cell` etc. from template strings (map breakpoints to literal class names).
- Next dev + Playwright: never run two dev servers on one `.next` (kill and wait for the port to free before `rm -rf .next`); a click can land before hydration and do nothing — retry with `toPass`, and make critical buttons work as plain forms (demo sign-in posts and redirects).
- `executor.NextStep` must compare `units_snapshotted` with the mint supply (what `finalize_snapshot` checks); the program skips zero-balance holders, so counting registered investors loops forever.
- SQLite cannot ALTER a CHECK constraint: migration 006 rebuilds `users` (copy → drop → rename); with foreign_keys on, the drop cascades to `sessions`, so everyone signs in again once after the upgrade.
- CORS (decided, task 9601): public GET/HEAD reads echo the request Origin with `Vary: Origin` and never send `Access-Control-Allow-Credentials`; writes get no CORS headers. Scanners flag it — do not change `corsReadOnly` in feature tasks (it caused rebase conflicts across parallel branches).
- Solana DvP (`dvp34bdbcEm4f4FCUjGV4mDAkDshaQR4LkK8fdcsyZq`, v0.1.0, upgradeable by the Foundation): no npm client — render one with Codama from `idl/dvp_swap_program.json` of solana-foundation/dvp; `SwapDvp` is 458 bytes with no discriminator; its escrow ATAs are created frozen for our bond mint; while the mint is paused Settle, Cancel and Reclaim all fail with Token-2022 error 0x43; Settle needs all four user ATAs to exist. LiteSVM tests load the devnet binary (`make fixtures`).
- Codama renderers-js: a second client in the same package needs `generatedFolder` (default `src/generated`); `clients/ts/scripts/codama.ts` renders the Solana DvP client into `src/dvp/generated`, and both folders are in the CI drift check and the eslint ignores. Its `SwapDvp` encoder writes 450 bytes for `earliestSettlementTimestamp: None` (the program stores a fixed 458 with a sentinel), so build test fixtures with `some(…)`.
- `@sqds/multisig` 2.1.4 only speaks `@solana/web3.js` v1: `clients/ts/scripts/demo-squads.ts` is the one deliberate web3.js-v1 exception outside apps/web (both devDependencies); Kit instructions are converted by `src/lib/squads.ts`. Its `rpc.*` helpers send without confirming — poll the signature before the next step.
