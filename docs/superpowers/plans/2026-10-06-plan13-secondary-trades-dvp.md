# Plan 13 — Secondary trades settled by Solana DvP

> **For agentic workers:** each task below is one queue task (`tasks/todo/<id>-*.md` says "implement task <id> of this plan"). Read **Read first**, then implement. Steps use checkbox (`- [ ]`) syntax.

**Goal:** two registered investors of a series trade bonds against the series' cash asset; the trade settles atomically through the Solana Foundation's DvP program (`dvp34bdbcEm4f4FCUjGV4mDAkDshaQR4LkK8fdcsyZq`, released 2026-10-06, devnet and mainnet), with the registrar as settlement authority, and never weakens the record date.

**What already exists (task 1301, on-chain):** `admit_trade`, `release_trade(force)`, account `TradeAdmission`, counter `Series.open_trades`, `strike_record` fails with `TradesInFlight` while a trade is admitted. Rules: `docs/03-domain.md` §4a; interfaces: `docs/02-architecture.md` rows 8, 19, 20; evidence: `reports/dvp-spike-2026-10-06.md`; tests: `programs/qupon_bonds/tests/trade.rs` (the instruction encodings of the DvP program are in its helpers). The generated Qupon client already has `getAdmitTradeInstruction*`, `getReleaseTradeInstruction*`, `fetchTradeAdmission`, `Series.openTrades`.

**Facts about the DvP program (v0.1.0) every task relies on**
- Qupon never CPIs into it. Trade record `SwapDvp` = PDA `["dvp", settlement_authority, user_a, user_b, mint_a, mint_b, nonce u64 LE]`; nonce tombstone `["nonce", swap_dvp]`; escrows = ATAs of the `SwapDvp` PDA. `user_a` = seller (bond leg, `mint_a`), `user_b` = buyer (cash leg, `mint_b`).
- `CreateDvp` is permissionless (the payer signs). Funding is a plain `TransferChecked` to the escrow ATA — there is no funding instruction. Only the settlement authority signs `SettleDvp` / `CancelDvp`; both close the record and the escrows. `ReclaimDvp` lets a party take back its own leg.
- The bond escrow is created frozen; only `admit_trade` thaws it. Settle needs all four user ATAs to exist (seller cash, buyer bond, seller bond, buyer cash).
- While the bond mint is paused, settle, cancel and reclaim fail (Token-2022 error 0x43).
- No npm package: the client is rendered with Codama from `clients/ts/idl/dvp_swap_program.json` (vendored from solana-foundation/dvp, commit `df9919ed`, MIT).

Do not touch `corsReadOnly`.
- Tests use the brief's holders (10 / 25 / 65 units, face 1,000 KZT = 100,000 tiyn): the reference trade is **5 bonds at par = 500,000 tiyn**.

## Review Focus
- A trade is never left admitted by a CLI or API path that reports success: create + admit and settle/cancel + release each go in **one transaction**.
- `trade:fund` refuses a record whose on-chain terms differ from what the investor was shown (verify before funding).
- A record date with an open trade: the operator sees why the strike is blocked and how to clear it; nothing auto-cancels a trade silently.

- [ ] Commands (all take the global options; JSON on stdout):
  - `trade:create --series <name> --seller <addr> --buyer <addr> --units <n> [--price <minor units per bond, default face value>] [--expiry-min <n, default 60>] [--ref <text ≤ 64 bytes>]` — registrar signs **one transaction**: `CreateDvp` (settlement authority = registrar, random 64-bit nonce from `crypto.getRandomValues`, destinations unset) + `admit_trade`. Output `{swapDvp, escrowBond, escrowCash, nonce, units, cashAmount, signatures}`. `cashAmount = units × price` in bigint.
  - `trade:fund --series <name> --trade <swapDvp> --side seller|buyer` — investor signs (`--keypair`). Reads the record, checks the signer is that side's party and the mints are the series' bond and cash mints, then sends one `TransferChecked` of exactly the leg amount to the escrow. Refuses if the leg is already funded.
  - `trade:settle --series <name> --trade <swapDvp>` — registrar signs one transaction: `SettleDvp` + `release_trade(false)`.
  - `trade:cancel --series <name> --trade <swapDvp> [--force]` — registrar signs one transaction. Without `--force`: create-idempotent for the buyer's cash ATA, `CancelDvp`, `release_trade(false)`. With `--force`: create-idempotent for the seller's bond ATA, `release_trade(true)` only (the DvP record stays open; print a hint that the buyer reclaims the cash). Output includes `returnedUnits`.
  - `trade:list --series <name>` — every `TradeAdmission` of the series (`listByKey`-style filter: discriminator + series at offset 9, size from `getTradeAdmissionSize()`), each joined with `readTrade` and both escrow balances: `{swapDvp, escrow, seller, buyer, units, cashAmount, admittedAt, fundedUnits, fundedCash, status}`.
  - `state:dump` gains `trades` (same rows) and `openTrades`.
