## Goal
Production (both servers share one Helius devnet key) is rate-limited: in 15 min the new server logged 345
`rpc call failed, retrying … getProgramAccounts() … status code: 429`, 133 `scheduler: list series` errors and 32
`upstream call failed` (the web shows "chain read failed"); the old server 465 × 429. Every scheduler tick and many API
requests re-scan program accounts (`internal/chain/client.go` `GetProgramAccounts`, used by AllSeries, open actions,
investors, entitlements, trade admissions; callers in `internal/scheduler`, `internal/api/{rest,showcase,admin,reports}.go`).

## Do
1. One cache at the single choke point `chain.Client.GetProgramAccounts`: key = discriminator + filters; TTL default 3 s
   (env `RPC_GPA_CACHE_TTL`, `0` disables); concurrent identical calls share one RPC request (singleflight —
   `golang.org/x/sync/singleflight` only if already in go.mod, otherwise a small mutex+wait map). Return copies so callers
   cannot mutate cached slices.
2. Freshness after writes: every CLI step changes chain state — invalidate the whole cache when an executor step finishes
   (hook from `internal/executor` `Run`/`RunRaw` completion, or the scheduler/sandbox call sites; one place, not per caller).
3. 429: `withRetry` (client.go:336) — on HTTP 429 back off exponentially with jitter (e.g. 0.5 s, 1 s, 2 s; honour
   `Retry-After` if the error exposes it) instead of the linear quick retry; other errors keep today's behaviour.
4. Tests: cache hit within TTL (one RPC call for two reads), miss after TTL, invalidation after an executor step,
   singleflight (N concurrent reads → 1 call), 429 backoff path (fake RPC). Keep every existing test green.
5. Worklog: expected call reduction (count gPA calls per scheduler tick before/after with the fake RPC).
