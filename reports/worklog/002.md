# 002 — devnet wallets, tKZT mint, config, funding helpers

## What changed
- `ops/wallets.sh`: prints the faucet.solana.com URL + address when all airdrop retries fail (rest was already in place).
- `clients/ts/scripts/create-tkzt.ts`: Token-2022 tKZT mint (dec 2, MetadataPointer+TokenMetadata, mint authority registrar), mints 100M tKZT → issuer, 1M → each investor; idempotent via `config/devnet.json` + on-chain existence check. Mint keypair kept at `~/.config/qupon/tkzt-mint.json`.
- `clients/ts/scripts/fund-usdc.ts`: idempotent USDC ATAs for issuer+investors, Circle faucet instructions per address, balance report.
- `clients/ts/src/lib/`: `config.ts` (typed loader/updater + placeholder logic, vitest), `keys.ts` (`loadKeypair(envVar)` → KeyPairSigner), `tx.ts` (rpc, blockhash send with 1 retry, confirmation polling).
- `config/devnet.json`: `tkztMint = HQWXGhNN3SUuaauG1z3vTjzfHRshJxdRYLF9gzzhFmsF` (created on devnet; issuer holds 100,000,000 tKZT, investors 1,000,000 each; USDC ATAs exist, wallets already had 20 USDC).

## Decisions / gotchas
- `InitializeMint2` (1-account) fails InvalidAccountData on Token-2022 v11 devnet; used the package's `getCreateMintInstructionPlan` (InitializeMint v1 + rent sysvar) — the empirically tested path.
- @solana-program/token-2022 0.19 predates Kit 8: `findAssociatedTokenPda` is async, `getCreateMintInstructionPlan` needs a promise-style `{ getMinimumBalance }` shim instead of the rpc.
- USDC faucet cannot be automated (task said so): script prints per-address instructions.
