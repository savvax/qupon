# 053 — compute-unit benchmarks of the batch instructions

- New `programs/qupon_bonds/tests/cu_benchmarks.rs`: measures `snapshot_batch` (1/5/8), `pay_batch` (1/5/8/10), `retire_batch` (1/5/12) and the single calls (strike, finalize, fund, complete, admit/release trade, forced release); asserts every transaction < 1.4M CU and every CLI-size batch < 600k CU. `reports/cu-benchmarks.md` is written only with `QUPON_WRITE_CU_REPORT=1`; "Batch sizing" in `docs/02-architecture.md` quotes the headline numbers.
- Decision: no mollusk-svm. The repo already runs the real program binary in LiteSVM and `Env::send` returns `compute_units_consumed`, so the numbers come from there with no new dependency.
- Added beyond the task text: worst-case rows (Token-2022 cash + 15% withholding tax for pay, suspended/frozen accounts for retire), because the plain SPL path is the cheapest one and tKZT is Token-2022. Result: heaviest CLI batch (retire 12, frozen) ≈134k CU = 22% of the 600k limit; no constant needs changing.
- Watch: the plain SPL cash leg runs on LiteSVM's bundled p-token build, not a devnet dump; `snapshot_batch` varies by ~±6% between runs (random keys → PDA bump searches, 1,500 CU per iteration), so regenerating the report changes its numbers slightly.
- Watch: LiteSVM does not enforce the 1232-byte packet size — the 10-holder `pay_batch` row is a compute figure only. The DvP `CreateDvp` builder is duplicated from `tests/trade.rs` (private helpers there); move both to `tests/common` if a third user appears.
