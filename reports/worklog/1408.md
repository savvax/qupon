# 1408 — CLI reports completed batches on failure; registrar records them

- `clients/ts/src/commands/action.ts`: new `runBatches` helper wraps the snapshot/pay batch loops; on a mid-run failure it prints `{ok:false, error, batches, results}` on stdout, sets exit code 1, rethrows. Both commands now route through it.
- `services/registrar`: executor already parsed failure JSON incl. `results` (doc updated); `scheduler.execute` and the `/advance` handler record one activity row per completed batch signature before returning the error.
- Tests: `action.test.ts` (send fails on 2nd call → 1 result on stdout, exit 1), `scheduler_test.go` and `advance_test.go` (fake CLI exit 1 + partial JSON → activity rows, error surfaced).
- Decision: skipped prettier on the TS files — no repo prettier config exists and defaults would reindent entire files to spaces; kept the repo's tab style for a reviewable diff. `gofmt -w` applied to changed Go files.
- Watch: `action:retire` (lifecycle.ts) still drops partial batch signatures on failure — same pattern, out of scope here.
