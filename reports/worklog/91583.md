# 91583 — registrar survives the RPC rate limit

- `chain.Client.GetProgramAccounts` now caches scans (key = discriminator + memcmp filters, TTL 3 s default, `RPC_GPA_CACHE_TTL=0` disables), singleflights identical concurrent scans into one RPC request (mutex+wait map; `x/sync` not in go.mod), and returns deep copies so callers cannot mutate the cache.
- Freshness: every completed CLI invocation fires `executor.OnStepDone` (set in `cmd/registrar/main.go` to `chainClient.InvalidateProgramAccounts`), also on failure/timeout — a partial batch can still change state.
- 429: `withRetry` detects `*jsonrpc.HTTPError{429}` and backs off 0.5 s/1 s/2 s ±25% jitter with a 4th attempt; Retry-After is not exposed by solana-go. Other errors keep the old linear retry.
- Measured with the fake RPC (`TestGPACacheCallReduction`): one refresh cycle (scheduler tick + dashboard reads) went from **8 to 4** gPA requests — one per distinct scan key; per 30 s production tick with N series the win scales with API traffic sharing AllSeries/investor scans within the TTL.
- Watch: demo cadence ticks every 2 s with a 3 s TTL, so consecutive ticks share cached scans; if a demo ever looks one tick stale, lower `RPC_GPA_CACHE_TTL` — invalidation after CLI steps already covers writes.
