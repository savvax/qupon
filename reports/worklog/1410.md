# 1410 — CLI pay_batch recreates closed holder cash ATAs idempotently

- `clients/ts/src/commands/action.ts` (runPay): one `fetchEncodedAccounts` detects missing
  (closed) cash ATAs; `ensureCashAtas` prepends `createAssociatedTokenIdempotent` at the
  stored `investor.cash_ata` (settle.rs requires exactly that key) before each pay_batch.
- Tx-size: 8 pay triples + inline creates can exceed 1232 B, so `payBatchBytes` +
  `splitPayBatch` (pure, order-preserving) split a batch when creates would overflow;
  normal all-open batches are unchanged (still 8).
- Tests: `action.test.ts` — instruction inspection (idempotent discriminator `[1]`, ATA
  program, roles incl. payer as writable signer) + sizing/split cases (all-open, mixed,
  all-closed) + none/all creates. 18 tests green; `make verify` OK.
- Watch: registrar pays ATA rent (~0.002 SOL) for recreated accounts; byte estimate is
  analytical (52 B safety margin) — if devnet ever rejects a split batch, lower
  PAY_TX_BYTE_LIMIT rather than PAY_BATCH_MAX.
