# 1419 — web/registrar: redemption escrow alert, next-step by units, org website scheme

- `deriveAlerts` escrow-short now requires Σ net + tax + `perUnitPrincipal × unitsSnapshotted` (no-op on coupons: perUnitPrincipal is 0 there). Logic moved to `_components/alerts.ts` (vitest cannot transform `.tsx`), re-exported from Pipeline for the page.
- `nextStep` RecordStruck: 3rd param is now `supply?: bigint` (page passes `series.totalIssued`); units ≥ supply → finalize, supply 0 → "no bonds outstanding — nothing to snapshot", mirroring Go `executor.NextStep`. Dropped the `listInvestors` fetch (holder counts lie: zero-balance investors are never snapshotted).
- Org website: `validWebsite` (http/https prefix, empty clears) enforced on PATCH `/org` and admin create/patch (admin writes the same field OrgControls uses — same sink, so both gates). Admin orgs page links only http(s) values via `httpHref`, everything else renders as text.
- Watch: `totalIssued` is the supply proxy for the web console; it diverges from live mint supply only if units were burned outside a closed action.
