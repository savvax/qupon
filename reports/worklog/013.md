# 013 — qupon CLI (series/investor/action/state + auto-batching)

- Added `src/cli.ts` (commander wiring only) and `src/commands/{index,common,series,investor,action,state}.ts` + `src/commands/action.test.ts`; reuse of lib helpers (daycount, batch, format, explorer, pda, tx, keys, config) — nothing reimplemented.
- `action:announce` derives period bounds (period_start/next_coupon_date), rate and accrual days from the on-chain Series, matching the program's EntitlementCalcMismatch checks; corp id defaults to `<series>-INTR-####`. `action:snapshot`/`action:pay` list holders via getProgramAccounts (discriminator+series memcmp, base64 filters), sort by owner ascending and chunk 8/10; pay only passes still-Snapshotted entitlements so re-runs and 0-balance holders are safe.
- Global `--rpc/--keypair/--json` accepted before or after the command name; signer resolution `--keypair` > `QUPON_KEYPAIR` > role env. Tx output is one `{ok,signature,slot,…}` JSON per tx on stdout (batch commands print one summary object with per-batch results); logs/explorer links on stderr; exit ≠ 0 on failure.
- Watch: `action:strike` and other authority commands pick the role from whether `--index` was passed (default open action → registrar keypair); task 018 adds retire/close/vote/meeting and may want an explicit `--as` role flag.
- Vitest: pure `sortedBatches` for 0/7/8/9/23 holders at both batch limits + owner-byte ordering; `pnpm build` produces `dist/cli.js`, `node dist/cli.js --help` lists all commands.
