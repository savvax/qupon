# 91587 — 3-minute sandbox replay

- `/[locale]/sandbox/replay` plays `apps/web/public/replay/sandbox.json` (client-side fetch) with the live
  `SandboxView` via two new optional props (`source`, `replay`): no registrar/RPC call at view time, scenario /
  cure / claim buttons hidden, recorded scenario results appear in the panels at their recorded time.
- Virtual clock in `src/lib/replay.ts` (pure, unit-tested): every inter-frame gap capped at 3 s, then the whole
  timeline scaled down if it still exceeds 180 s (dense recordings compress uniformly); play/pause, ×1/×2,
  restart, progress bar with step names; sticky REPLAY banner + "not recorded yet" state (en/ru/kk).
- Recorder: `node apps/web/scripts/record-sandbox.mjs <webAppBaseUrl> [out]` — creates the sandbox exactly like
  `SandboxStart` (POST /api/bo/demo/sandbox, requestId), polls every 2 s, keeps changed frames only (serverTime
  ignored), runs dvp_trade then non_kyc_transfer after "Coupon 1 paid", stops at the live e2e's end state
  (refusal visible), 20-min cap, exit ≠ 0 on failure. Dry-run against the mock dev server: 10 frames, 195 s,
  32 signatures, 119 331 bytes, plays in ~17 s. **The lead records the real run against production and commits
  `apps/web/public/replay/sandbox.json`** (gitignored here).
- e2e fixture `apps/web/e2e/fixtures/sandbox-replay.json`: 20 331 bytes, 2 frames + 2 recorded scenarios,
  generated from the mock (one id so ticker/holders stay coherent); spec asserts the banner, ×2 playback to
  "Coupon 1 paid", read-only scenario cards, and that no request touches the API or an RPC.
- Watch: if a real recording exceeds 180 s after the 3 s cap (very dense run), the planner scales it down —
  countdowns then jump more; if the lead's recording shows hydration warnings, check `serverTime` skew handling
  in `SandboxView` first.
- Round 1 review fix: `NetworkChip` no longer polls the cluster RPC on `/[locale]/sandbox/replay` (pathname guard
  on `live`, `qp-live` dot follows it); `NetworkChip.test.tsx` asserts no `getSlot` fetch there and one fetch on
  other routes. Web unit suite 304 passed.
