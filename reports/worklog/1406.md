# 1406 — CLI survives client disconnect; demo sign-in not one shared rate bucket

## What changed
- `internal/executor/executor.go`: "timed out after 120s" is reported only for
  `context.DeadlineExceeded`; a parent cancellation now says `cancelled: context canceled`.
- `advance.go`, `approvals.go` (approve), `issuer.go` (fund): the CLI runs on
  `context.WithoutCancel(r.Context())` — a browser disconnect can no longer kill a
  mid-batch step; the 120 s executor cap stays the only deadline. Approve also uses the
  detached ctx for Revert/Finish/InsertActivity so a disconnect cannot strand the row in
  `running`.
- `apps/web/src/app/api/session/start.ts`: forwards the inbound `X-Forwarded-For`
  (set by Caddy) to the registrar, so each visitor gets its own 20/min sign-in bucket.
  Registrar trust rules unchanged (last XFF hop, internal network only).

## Tests
- `TestRunParentCancelIsNotATimeout` (sleep shim, parent cancelled at 50 ms).
- `TestSignInRateLimitPerForwardedIP` (two XFF values → separate buckets; 21st → 429; last-hop rule).

## Watch

  if judges hit disconnects there.
