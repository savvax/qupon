# 9309 — security hardening from the pre-deploy review (lead)
An independent read-only review of the back-office surface; findings verified by the lead before fixing.
- **RPC key never in errors** (high): solana-go prints the request URL in its errors, which reached logs and public 502 bodies. `chain.NewRPC` gives solana-go a keyless URL and adds the query on the wire (`keyQueryTransport`); used by the chain client and the ingest poller. Test: a non-JSON 429 error does not contain the key, the server still receives it. The executor also redacts `api-key=` in CLI output (`redactKeys`).
- **Load limits** (high): at most 2 concurrent CLI processes (others queue on their request context); `MaxBytesReader` on advance and series creation; server Read/Idle/Write timeouts; per-client-IP limit (20/min, last X-Forwarded-For hop set by Caddy) on demo and password sign-in. The per-demo-user write throttle remains task 9203.
- **Login limiter** (medium): only failures count (no lockout of a real operator by others), unknown emails pay a dummy bcrypt (no timing oracle), idle keys are swept.
- **Open redirect** (medium): `safeNext` rejects control characters and backslashes (`/%09/evil.com`).
- **Read cache** (medium): only empty or `?lang=` queries are cached, at most 1,000 entries, and `/auth/*` posts no longer flush it.
- Low: logout checks Origin; the `/api/bo` 502 is a constant message; expired sessions are pruned on every new session.
- Not changed (by design for the demo): demo users have the same powers as real accounts of their role; `GET /approvals` stays public (argv only, no secrets).
