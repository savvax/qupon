# 91585 — shared RPC cool-down after a 429

- `internal/chain/client.go`: new `coolDown` gate (mutex + until) on `Client`; any 429 in `withRetry`
  arms it to `now + rateLimitBackoff(base, attempt)` (never earlier), and every RPC attempt — first
  ones included — waits for it before hitting the server. Per-call attempt counts, the non-429 linear
  retry and the 429 backoff schedule are unchanged. Logged once per episode
  (`rpc rate-limited, cooling down`, `until`), never the URL or key.
- `internal/ingest`: untouched — it has no retry loop around its RPC (errors surface to the 10 s poll
  ticker), so there is no second backoff to unify.
- Tests: `TestRateLimitCoolDownSharedAcrossCalls` (a concurrent call's first attempt waits out the
  gate; base shrunk to 40 ms), `TestNon429FailureDoesNotCoolDown`. All existing tests green,
  `make verify` OK.
- Watch: the gate makes every caller wait together — a long episode (4 s cap per push) pauses reads
  too; if that ever hurts, cap or interrupt the gate rather than per-caller retries again.
