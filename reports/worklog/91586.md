# 91586 — in-process devnet RPC gateway

- Added `services/registrar/internal/rpcgw` (task 91586): JSON-RPC gateway inside the registrar — 4 kept-alive upstream conns, token buckets (8 req/s total burst 16, 3.5 req/s per method burst 8, waiting never refusing), cache+singleflight by method+canonical params (TTLs per task; null `getTransaction` never cached; tx cache bounded at 2000), successful `sendTransaction` clears the 1.5 s account-state entries, cached/shared answers re-wrapped with the caller's id, batches forwarded uncached at one token per element, HTTP and JSON-RPC 429 → gateway-wide cool-down (1 s doubling to 8 s ±25 %, reset on success) retried up to 5×. One `rpc gateway` stats log per 60 s (calls, hits, shares, 429s, max queue wait, top-5 methods) which also sweeps expired entries.
- Wiring: `main.go` starts it on `RPC_GATEWAY=1` / `RPC_GATEWAY_ADDR` (default 127.0.0.1:8899) before the chain client/poller/executor, sets `RPC_URL`+`RPC_FALLBACK_URL` so CLI subprocesses route through it; the startup log still prints the redacted real upstream. `ingest.NewPoller` no longer opens a direct public-devnet fallback when the RPC host is loopback. `ops/deploy-vps.sh` writes `RPC_GATEWAY=1`. `golang.org/x/time/rate` promoted from indirect to direct in go.mod (already in go.sum).
- Measured (fake upstream, `go test ./internal/rpcgw -run TestBurst -v`): a dashboard-style burst of 60 requests → 15 upstream calls (75 % reduction); hard ceiling by pacing is 8 req/s ≈ 480 upstream calls/min, under the public per-IP 100/10 s. Before: every CLI process hit devnet directly (~130 429/min on the judge sandbox).
- Watch: the gateway is a single process bottleneck — if the box ever runs two registrar processes they each get their own gateway and their combined pacing can exceed the IP limits again; the sendTransaction cache clear only covers the gateway's own cache, so `chain.Client`'s GPA cache invalidation (task 91583 hook) stays in place and must not be removed.
- Watch: `getVersion`-class 10-minute TTLs assume cluster identity never changes mid-run; acceptable for a demo run. `reconcile.go` was already unformatted at HEAD (not touched — pre-existing, `make verify` does not gate gofmt for Go).
