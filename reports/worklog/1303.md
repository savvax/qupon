# 1303 — Go: trades in the chain reader, API, step gating

- Chain: `Series.OpenTrades` (u32, carved from `Reserved`, now 60 bytes), `TradeAdmission` + `DecodeTradeAdmission` + `FetchTradeAdmissionsBySeries` (memcmp series at offset 9, oldest first). `ReadModel` gained that lister and `GetAccountWithOwner` (the cash mint's token program places the cash escrow ATA).
- API (`internal/api/trades.go`): `GET /series/{mint}/trades`, registrar `POST /registrar/series/{mint}/trades` + `…/{swapDvp}/settle|cancel`, demo `POST /demo/investor/series/{mint}/trades/{swapDvp}/fund`; `SeriesDTO.openTrades`. Routes carry the series mint (the CLI needs `--series`, and the admission is looked up in that series → `404 trade_not_found` before any CLI run); plan 13 tasks 1303/1304 and `docs/02-architecture.md` updated to match.
- Step gating: `executor.NextStep` takes `openTrades`; an Announced action with trades open returns no step and `open secondary trades: settle or cancel them first (N)` in `/advance` and in the scheduler (which only waits).
- Decisions: demo funding finds the keypair by deriving the public key of each file named in `QUPON_INVESTOR_KEYPAIR` / `QUPON_INVESTOR1..3_KEYPAIR` per request (solana-go, no new dependency; an unreadable file is skipped and logged by variable name only). `loadSeries` in `rest.go` became the package function `seriesOf` so trades reuse the series 404. `demoServer` (test helper) now takes a `ReadModel`.
- Watch: the demo fund route keeps the `investor_demo` guard, so a registrar session gets 403 there — the "Fund both legs (demo)" button on the registrar page (task 1304) needs a demo-investor session or a lead decision. `GET …/trades` sits behind the read cache: a leg funded straight from a wallet shows after the TTL. `golangci-lint` reports one finding that predates this task (`internal/api/org.go:268`, QF1001); `make verify` does not fail on it.
