# 1104 — Solana wallet connection UX (spec §5.7)
- `components/wallet/WalletUX` (context, replaces wallet-adapter's English modal): detects Wallet Standard wallets (Installed/Loadable); "Connect wallet" connects the only one directly, opens a picker for several, and for none a dialog with why/install links (Phantom, Solflare, Backpack), mobile deep links that reopen the page inside the wallet, and a read-only **view by address** (persisted per browser). Errors from the provider's `onError` (rejected, not ready, timeout) are explained in the dialog with retry.
- `WalletButton` in the public header (label from xl) and every cabinet top bar: "Connect Phantom" when one wallet is installed; connected → chip with menu (copy, explorer, link to account, disconnect); watch → amber chip (connect, stop viewing).
- Investor cabinet: new chooser (detected-wallet line, view by address, demo); identity mode `watch` (read-only badge; placement/vote ask to connect).
- Hydration: wallet lists render empty until mounted (extensions are invisible to the server) — e2e asserts no console errors with 0/1/2 wallets.
- e2e/wallets.ts injects fake Wallet Standard wallets (0/1/2, rejection switch); e2e/wallet-connect.spec.ts covers all paths + RU. Branch carries 605's commits (NetworkContext): merge after 605.
