# 1510 — hook-gated record date in the product flow, permissionless crank, set hash
- Hooked series: checkpoints created by `register_investor` / `admit_trade` (late ones start at `record_seq`, counted in `ckpt_late`); `snapshot_batch` takes positions (investor ATA or admitted escrow → seller) from `record_at`, recomputes the holder's entitlement on total units, advances checkpoints; `finalize_snapshot` proves completeness by counts and `Σ ≥ supply`, disarms the gate for INTR/PCAL/BMET; mints blocked while pending; forced release = burn + mint (no hook re-entrancy), release refused inside the record window.
- Why counts and `Σ ≥ supply`: a holder can burn after their snapshot (burns skip the hook) — with `Σ == supply` that blocked finalize for everyone (cheap DoS); counts keep "nobody missed" exact.
- Legacy series: strike → pause → snapshot unchanged, INTR/PCAL resume at finalize; strike/snapshot/finalize/pay/complete/retire are permissionless; new actions use the order-independent set hash (hash_scheme 1).
- Existing tests changed only where behaviour changed by design (D2/D3): settle `only_issuer_or_paying_agent_funds` (pay → Underfunded instead of Unauthorized), redemption `anyone_retires_only_registrar_closes`, snapshot `strike_guards`, `snapshot_review_paths`, `expected_hash` (set hash). New accounts (`checkpoint`, `escrow_checkpoint`) are appended last to keep account indices stable.
- CLI `action:snapshot` builds hooked positions (incl. open admissions); release passes the escrow checkpoint. Go: `HashScheme` decoded, reconcile uses entitlement units on hooked series and the set hash for scheme 1.
- Watch: clients that move bond units on a hooked series must add the hook extras (task 1516).
