# Qupon kit — как запустить непрерывную работу агентов (инструкция для человека)

Этот набор файлов превращает пустой репозиторий в проект для side track **KASE × Superteam Kazakhstan** (Colosseum Crypto World's Fair). Дедлайн: **13 октября 2026, 11:59 по Алматы**; цель подачи — 12 октября, 20:00. Полное описание проекта, roadmap и задачи — в документе «Корпоративные действия на Solana (KASE): проект и план реализации» и в `docs/`.

## Запуск за 30 минут

1. Создай публичный репозиторий на GitHub, склонируй, скопируй содержимое кита в корень, `git add -A && git commit -m "chore: qupon kit" && git branch -M main`.
2. `bash ops/bootstrap.sh` — ставит Agave 4.3.0, Anchor 1.2.0, Node 22, pnpm, Go 1.25, pi, Surfpool, Claude Code (Linux/macOS). Добавь строку PATH из вывода в профиль оболочки.
3. `cp .env.example .env` и заполни: `HELIUS_API_KEY`/`RPC_URL` (бесплатный тариф Helius), `ZAI_API_KEY` (кабинет Z.ai, план GLM Coding). `AUTO_PUSH=1`, если хочешь, чтобы оркестратор сам пушил `main`.
4. `bash ops/wallets.sh` — создаёт 7 ключей в `~/.config/qupon/` и просит SOL. Если airdrop не прошёл — faucet.solana.com (вход через GitHub даёт больше), USDC — faucet.circle.com. На ключ регистратора нужно 3–5 SOL под деплой программы.
5. `claude` в корне репозитория → подтверди доверие к папке → `/login` (Max). Выйди. `pi auth check --provider zai` должен вернуть «ready» (или `export ZAI_API_KEY=...`).
6. `bash ops/doctor.sh` — все версии зелёные.
7. **Сессия 0** (один раз, интерактивно): `claude` → вставь `Follow prompts/MASTER.md, Session 0.` Claude проверит окружение, очередь и сам сделает задачи 001, 003, 005 (каркас, математика, скелет программы). Это 1–2 часа.
8. `bash ops/tmux.sh` — поднимает четыре цикла (`claude-1`, `glm-1`, `glm-2`, `flash-1`) и доску статуса. `tmux attach -t qupon` — смотреть; `touch tasks/.stop` — остановить всё после текущих задач.

## Как это работает

Каждый цикл берёт первую задачу своего тега, у которой все зависимости в `tasks/done/`, создаёт git worktree на ветке `task/<id>`, запускает агента с преамбулой и текстом задачи, ждёт `DONE:<id>`, **сам** прогоняет `make verify`, делает rebase и fast-forward merge в `main`, переносит задачу в `done/`. Красный `verify` → задача возвращается в очередь; после двух неудач GLM-задача переходит к Claude; после трёх неудач Claude — в `failed/` и вопрос тебе. Каждые 5 слияний — проход ревьюера (Sonnet, чистый контекст) и планировщика (Claude в plan-режиме, пишет только файлы задач). Ночью (`ops/nightly.sh` по cron) — `make demo` на devnet и дневной отчёт.

Лимиты: Claude Max — одно 5-часовое окно и недельный лимит общие с claude.ai, поэтому один Claude-рабочий; при сообщении о лимите цикл спит с удвоением до часа. Z.ai Pro (legacy): ~400 промптов за 5 часов; GLM-5.3 в пиковые часы (пн–пт 11:00–15:00 Астана) стоит втрое — оркестратор в это время берёт для GLM только T0-задачи (снять ограничение: `FORCE_PEAK=1`). Flash работает всегда.

Безопасность: у pi нет системы разрешений, а bypass-режим Claude документирован только для изолированных сред — запускай всё под отдельным пользователем Linux или в контейнере `ops/Dockerfile`. Ключи только devnet. `.env` и keypair-файлы в `.gitignore`.

## Твоя ежедневная рутина (30–60 минут)

1. `bash ops/status.sh` и `reports/daily-YYYY-MM-DD.md` — что слилось, что застряло.
2. `HUMAN_TODO.md` — ответь под пунктами; для заблокированной задачи удали строку `blocked_reason:` в её файле, когда причина устранена.
3. `make demo` — посмотри глазами суммы, статусы, тексты уведомлений. Юридическая выверка формулировок — твоя зона.
4. 1-минутный видео-апдейт для Colosseum (вт, пт, пн).
5. Один внешний контакт в день для «подтверждения спроса» (организатор трека @d1asaur, знакомые в брокерах/ЦД/KASE).

Гейты: среда 22:00 — три сценария на devnet одной командой; пятница 22:00 — демо через UI; суббота 20:00 — заморозка функций; воскресенье — видео и формы; понедельник 20:00 — подача.

## Режимы работы

- **Оркестратор (рекомендуется)** — как описано выше: `ops/tmux.sh`.
- **Соло Claude** (если GLM недоступен): интерактивно `claude` → `Follow prompts/MASTER.md in solo mode` — Claude идёт по очереди по порядку id независимо от тегов; используй `/clear` между задачами. Или headless: `claude -p "$(cat prompts/MASTER.md) Solo mode." --permission-mode acceptEdits --max-turns 300`.
- **Контейнер**: `docker build -t qupon-worker -f ops/Dockerfile .` и запускай `ops/orchestrate.sh` внутри с `CLAUDE_BYPASS=1` в `.env` (включает `--dangerously-skip-permissions`; только внутри контейнера).

## Если что-то ломается

| Симптом | Что делать |
|---|---|
| `anchor build` ругается на platform-tools под Agave 4.3 | `anchor build --tools-version v1.57` (добавь в Makefile) или Agave 4.2.2 |
| Pausable CPI ведёт себя не так | запасной вариант в `docs/03-domain.md` §4: freeze всех счетов на дату фиксации |
| devnet режет RPC / airdrop | Helius-ключ в `.env`; faucet через GitHub; Surfpool для локальных e2e |
| «hit your … limit» в логах | нормально: цикл спит; при желании снизь `CLAUDE_MAX_TURNS` или переведи часть `claude`-задач на `glm` (`agent:` в файле задачи) |
| GLM испортил Rust | автоэскалация к Claude после двух неудач; можно сразу поставить `agent: claude` |
| конфликт слияния | ветка `task/<id>` сохранена; разреши руками или удали `blocked_reason:` после починки |
| агент ждёт решения | `HUMAN_TODO.md` → ответь → планировщик разнесёт по задачам |
